Plan: a fake clock for the whole stack

November 12, 2026

The plants batch only during their opening hours: Weinheim 06:00–18:00, Mannheim and Walldorf 05:00–20:00, Berlin time. In the evening, make demo’s orders wait for the next morning, the late pump has nothing to move, and make chaos has no ticket due during its cut. Recording the GIF would only work in the daytime. This plan lets the whole simulated world run at a different time of day, with the same shift in every service, so the hours stay real and the demo still has something to show.

Done when:

  • With CLOCK_OFFSET_HOURS set, every Pourline service reads the same shifted time: dispatch, ingest (including the operator’s integration workloads), the simulators, the demo, the plant-agent and ingest-cli. It defaults to 0, so nothing changes unless it is set.
  • Run in the evening, make demo shifts the world into the daytime by itself: the orders are planned for today, and the late pump moves loads. make k8s does the same, so make chaos has tickets falling due during the cut.
  • Times that operators read stay real: traces, metrics, and lastSuccessfulIngest (kubectl’s LAST INGEST column).
  • make test is green. make demo after 18:00 shows a diff for the late pump. CI’s e2e job is unchanged and stays green.

How

  • domain::clock: init_from_env() reads CLOCK_OFFSET_HOURS once at startup, and an invalid value stops the service with a clear error. now() returns the wall clock plus that offset. It goes in domain because every binary already depends on it, the plant-agent included.
  • Dispatch already takes its clock as a function (worker::run, api::router), so main passes domain::clock::now instead of Utc::now.
  • Simulators and the plant-agent start their existing Clock from domain::clock::now(). The demo and ingest-cli use it for their order times and replays.
  • Ingest stamps received_at with domain::clock::now(), because it becomes occurred_at for customers that send no revision, and dispatch orders revisions by it. The ingest-status KV gets the real time instead (decision 3).
  • Configuration: compose passes CLOCK_OFFSET_HOURS to every service. Both charts get clockOffsetHours (default 0). The operator adds the variable to the variables it hands to each integration workload, and chaos.sh passes it to its order pod.
  • Makefile: when CLOCK_OFFSET_HOURS isn’t set and Berlin time is outside 06:00–16:00, make demo and make k8s pick the offset that puts the world at about 10:00, and say so. make up keeps the real clock.
  • The README’s and the tape’s “record between 05:00 and 18:00” notes go. The README explains the variable, and you add one line to .env.example.

Steps

Step 1

The clock and the services. I write the tests first: domain::clock parses the offset and applies it, and rejects anything that isn’t a whole number of hours. Then every binary uses the clock, and the operator passes the variable on, with a test on the workload it builds. make test.

Step 2

Compose, charts, Makefile, docs. Then I run make demo tonight and check that the late pump moves loads. I run make k8s and make chaos and check that tickets wait out the cut, and that LAST INGEST reads seconds, not hours. Then you re-record the GIF whenever you like.

Decisions I need from you

#QuestionMy default
1How is the shift given?As a whole number of hours, the same in every service: CLOCK_OFFSET_HOURS=-10. The alternative is a time of day, “start at 10:00”, but each service would work out its own offset when it starts, so services that start seconds apart would disagree by those seconds.
2Who sets it?make demo and make k8s shift automatically when it’s evening, night or early morning in Berlin. Set by hand, CLOCK_OFFSET_HOURS always wins, including 0 to keep the real clock. The alternative is never to shift automatically, so you pass it yourself and the README says when.
3Which times stay real?Traces, metrics and lastSuccessfulIngest, because they describe the system rather than the simulated world. Everything about orders, plans, tickets and trucks moves.

Heads-up

  • While the world is shifted, plan times in the API and the demo don’t match the clock on the wall, but Jaeger and Grafana do. The demo prints the shift at the top.
  • A shifted world keeps running on: started at 20:00 with −10 h, it reaches the plants’ closing time around 04:00 real time.
